# 0001: リポジトリ構成とパッケージの依存方向

- Status: accepted
- Date: 2026-07-19

## Context

agentctl は、外部ツールを呼び出しながらタスクの状態遷移を管理する Go 製 CLI である。実装には、状態遷移のルール、設定の読み込み、Git や Docker Compose などの外部操作、CLI 入出力が含まれる。

これらを無秩序に同じパッケージへ置くと、状態遷移のテストにファイルシステムや外部コマンドが必要になり、変更の影響範囲も分かりにくくなる。一方で、初期段階から細かなレイヤーや汎用的な抽象を導入すると、小規模な CLI に対して構造が過剰になる。

そのため、次の条件を満たす最小限の構成を決める。

- 状態遷移のルールを外部 I/O から切り離してテストできる
- 外部ツールや保存方式の変更を、状態遷移の実装へ波及させない
- パッケージの役割と依存方向をコード上で判別できる
- 将来の可能性だけを理由にした抽象化やディレクトリを作らない

## Decision

Go の標準的な `cmd/` と `internal/` を使い、リポジトリを次のように構成する。

```text
agentctl/
├── cmd/agentctl/        # CLI のエントリポイントと依存の組み立て
├── internal/
│   ├── core/            # 状態遷移、ユースケース、外部操作のインターフェース
│   ├── infra/           # ファイル、Git、Compose、GitHub、Agent などの実装
│   ├── config/          # 設定ファイルの読み込みと検証
│   ├── doctor/          # 環境の非破壊チェック
│   └── cli/             # CLI の入力、表示形式、終了コード
├── config/              # リポジトリ管理対象の設定（秘密情報は置かない）
├── docs/decisions/      # Architecture Decision Record
├── scripts/             # 必要になった開発用スクリプト
└── test/                # パッケージをまたぐ統合テストと E2E テスト
```

単体テストは対象コードと同じパッケージに置く。`test/` は、複数パッケージや実際の外部プロセスを扱うテストに限って使用する。空のディレクトリは先に作らず、必要なコードが生じた時点で追加する。

### 依存方向

依存は外側から `core` へ向ける。

```text
cmd/agentctl ──→ core
      │          ↑
      ├────────→ infra/*
      ├────────→ config
      ├────────→ doctor
      └────────→ cli

infra/* ───────→ core
```

各パッケージには次のルールを適用する。

- `core` は状態遷移と処理の順序を決める。ファイル、ネットワーク、外部コマンドなどの I/O 実装には依存しない。
- `core` が必要とする外部操作は、利用側である `core` に小さな interface として定義する。interface には実際に利用するメソッドだけを含める。
- `infra` は `core` の interface を実装する。`infra` 配下の実装同士は直接依存させず、処理の組み合わせは `core` または `cmd/agentctl` で行う。
- `cmd/agentctl` は具象実装を生成して組み立てる。引数の解釈や終了処理は担うが、状態遷移のルールは持たない。
- `config`、`doctor`、`cli` はそれぞれの責務に閉じ、タスク進行の判断を持たない。

interface の名前や分割単位は、利用箇所が明らかになった時点で決める。実装前に網羅的な port 群を定義しない。

### 採用しない構成

- `src/` は設けない。Go では `cmd/` と `internal/` で実装コードの配置と公開範囲を表現できるためである。
- entity、usecase、presenter などのレイヤーを一律には設けない。責務の分離が必要になった場合に、具体的な変更理由とともに追加する。
- 汎用 repository interface やプラグイン機構は導入しない。保存先や Agent の差し替えには、`core` が必要とする操作だけを表す interface を使う。
- UI、デプロイ、拡張機構など、現在の CLI に存在しない機能の置き場所は用意しない。

## Consequences

### Positive

- 状態遷移を fake 実装で検証でき、単体テストが外部環境に依存しない。
- Git、Compose、GitHub、Agent などの詳細を `infra` に隔離できる。
- 依存の組み立て場所が `cmd/agentctl` に限定され、実行時に使われる実装を追いやすい。
- Go の言語機能で `internal/` の外部公開を防げる。

### Negative

- 外部操作を追加する際は、`core` の interface と `infra` の実装をそれぞれ用意する必要がある。
- `infra` の実装を直接組み合わせられないため、単純な処理でも `core` または `cmd/agentctl` に調整役が必要になる場合がある。
- パッケージ境界だけでは依存ルールを強制しきれないため、レビューとテストで逸脱を検出する必要がある。

## Follow-up

新しいトップレベルディレクトリ、共通レイヤー、または依存方向の例外が必要になった場合は、実際の利用例を示した上で別の ADR に記録する。
